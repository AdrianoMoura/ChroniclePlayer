# D-057

**Spec:** `feed.md`, `playback.md`

Three Watch Later refinements, all direct product-owner requests, same session, same pattern as D-050–D-056.

**(1) Auto-remove from Watch Later on open.** New `SettingsDto.watchLaterAutoRemove`, default **off**. While on, opening a video that's currently queued removes it from Watch Later immediately — the same effect as a manual untoggle, just triggered by opening rather than a click. No undo strip: a queued video already stays visible in the current in-memory list until the view is left and reopened, the same grace a manual untoggle already has, so a second undo mechanism would be redundant.

**(2) Up-next card wraps around.** The player's "up next" card (D-055) now wraps: reaching the last queued video suggests the oldest one again instead of going silent, since the user can start watching from anywhere in the queue, not just the front — combined with (1), this lets a user work through their whole queue by just opening videos. Guarded against suggesting the video that just ended (a one-item queue no longer loops onto itself). `core/feed.ts`'s `nextWatchLaterAfter` uses modulo wraparound instead of returning `null` past the last index.

**(3) Drag-and-drop reorder in the Watch Later view, list and grid alike.** Native HTML5 drag-and-drop, no new dependency.

The whole row/card is the drag source: `draggable`, click-and-hold anywhere on it starts the drag (no separate grab handle). Drop-target hit-testing lives one level up, on `FeedList`'s own per-item wrapper — the exact virtualized slot, with no dead zone around it, unlike the row/card rendered inside it (which has its own margin/gap that a plain row/card-level handler wouldn't cover). Grid's wrapper holds several cards side by side, so `resolveGridColumn` maps the pointer's x-position to the nearest card by dividing the wrapper's width by the column count. A fallback `onDragOver`/`onDrop` on the scrollable container itself (`.feed-scroll`) resolves to "insert after the last video" for empty space past the last item (e.g. a short list that doesn't fill the viewport) — the per-item wrapper handlers call `stopPropagation()` so this fallback only fires when the pointer isn't over any specific item.

Each video's own drop zone means "insert after it"; only the very first video also accepts "insert before" (nothing else can become the new first item) — `FeedList`'s `dragProps` resolves every other video's reported edge to `'after'` regardless of which half of it the pointer is over. The visual indicator (`.drop-indicator`) is purely decorative — `pointer-events: none`, flush with one edge of the hovered item — separate from hit-testing, which is the wrapper's job.

`onReorder(fromIndex, insertAt)` — computed at the point of drop from `(videoIndex, edge)`. Persists through a new `reorderWatchLater(videoIds)` IPC call (`StateRepository`) that reassigns `watch_later_pos` from the dropped order in one transaction, ignoring any id no longer in the queue.

Confirmed working live by the product owner.
