### B-141 — Search results and a non-subscribed channel's video listing show a live/upcoming/Premiere video as a plain "0:00" video instead of a Live/Premiere/Upcoming badge
- **Type:** bug · **Severity:** minor
- **Status:** Fixed · **Reported:** 2026-10-26 · **Target:** 0.16.3
- **Area:** feed
- **What happens:** the main synced feed (`FeedList.tsx`) shows a currently-airing or
  upcoming broadcast with the same Live/Premiere/Upcoming badge treatment (B-114/B-115/
  B-119/B-122) already built, and hides the (meaningless) duration while it's live.
  Free-text search results (`/` topbar) and a not-yet-subscribed channel's own video
  listing (B-131) never showed that badge at all — a live or upcoming video just read
  as a normal video with a "0:00" duration, since YouTube only reports a real
  `contentDetails.duration` once a broadcast ends.
- **Expected:** both lists use the same Live/Premiere/Upcoming badge and
  duration-suppression rule the main feed already has.
- **Code refs:** `src/ipc/contract.ts` (`SearchVideoResultDto`), `src/adapters/youtube/
  api-client.ts` (`search()`, its duration follow-up call), `src/platform/ipc/
  channel-handlers.ts` (`getChannelVideos`), `src/ui/SearchResults.tsx`, `src/ui/
  FeedList.tsx` (`liveBadgeState`/`liveBadgeLabel`, pre-fix location).
- **Resolved:** 2026-10-26 · **Commit:** 7fda1ff · **Outcome:** Fixed
- **Resolution:** `SearchVideoResultDto`/`api-client.ts`'s `SearchResult` video variant
  now carry `liveContent`/`liveStartedAt`/`liveEndedAt`/`isPremiere`, same as
  `FeedVideoDto`. `search()`'s duration follow-up call (`fetchVideoDetails`, formerly
  `fetchVideoDurations`) widened to also request `liveStreamingDetails,status` — still
  1 unit per call regardless of parts requested, same precedent `hydrate()` already
  set, no new quota cost; `liveContent` itself comes free from `search.list`'s own
  `snippet.liveBroadcastContent`. `channel-handlers.ts`'s `getChannelVideos` already
  received these fields from `hydrate()` (used only to compute `bucket`) but discarded
  them — now passes them through, no new API call needed there either.
  `liveBadgeState`/`liveBadgeLabel` moved out of `FeedList.tsx` into `format.ts` so
  `SearchResults.tsx` uses the exact same badge/duration-suppression rule as the main
  feed instead of a separate copy that could drift. `youtube-api.md` updated to
  document the widened `part` on the search duration follow-up. New regression test in
  `api-client.test.ts` covering a live+Premiere search result end to end. Checked via
  `npm run typecheck && npm run lint && npm test` (328/328); not run live (per
  [[no-live-app-verification]]).
